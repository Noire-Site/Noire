# Admin Dashboard — Design Spec
**Date:** 2026-03-23
**Project:** Nøiré (Vite + React + React Router + Supabase + Clerk)

---

## Overview

A protected admin dashboard at `/admin` that lets whitelisted users manage products. Auth is gated by Supabase Auth (email + password) plus an `admin_users` Supabase table. No generic admin UI library — styled to match the existing Nøiré dark aesthetic.

---

## Auth Flow

1. Any visit to `/admin/*` renders through `AdminGuard`
2. Guard calls `supabase.auth.getSession()` (async)
3. While checking: render a full-screen centered spinner on black background
4. **No session** → redirect to `/admin/login`
5. **Session exists** → query `admin_users` table: `SELECT email FROM admin_users WHERE email = ?`
6. **Email not found** → `supabase.auth.signOut()`, redirect to `/`
7. **Email found** → render the protected route

`/admin/login` renders a Supabase Auth email + password form. Session is persisted in `localStorage` automatically by the Supabase JS client.

**AdminGuard pattern (React Router v6):**
```jsx
// AdminLayout wraps all admin routes. AdminGuard sits inside for protected routes.
<Route path="/admin/login" element={<AdminLayout><AdminLogin /></AdminLayout>} />
<Route path="/admin" element={<AdminLayout><AdminGuard><AdminDashboard /></AdminGuard></AdminLayout>} />
<Route path="/admin/products/new" element={<AdminLayout><AdminGuard><ProductForm /></AdminGuard></AdminLayout>} />
<Route path="/admin/products/:id" element={<AdminLayout><AdminGuard><ProductForm /></AdminGuard></AdminLayout>} />
```
`AdminLayout` renders the outer black shell (logo + sign-out button). It shows the sign-out button only when a Supabase session exists. `AdminGuard` handles the async auth check and renders children only after confirming access.

**Bootstrapping the first admin user:**
1. Create a user in Supabase Auth (Dashboard → Authentication → Users → Invite)
2. Insert their email into `admin_users` via Supabase SQL editor: `INSERT INTO admin_users (email) VALUES ('you@example.com');`

## Form Fields → Supabase Column Mapping

| Form Label | Column | Input Type | Notes |
|---|---|---|---|
| Name | `name` | text | Required |
| Slug | `slug` | text | Auto-generated from name (kebab-case), editable |
| Category | `category` | dropdown | Men, Women, Unisex |
| Price | `price` | number (integer, ≥ 0) | Required |
| Sale Price | `sale_price` | number (integer, optional) | Nullable; no validation against price |
| Tags | `tags` | TagInput | jsonb column; stored as text array e.g. `["Sale","New Drop"]` |
| Sizes | `sizes` | checkbox grid | jsonb column; XS S M L XL XXL One Size → string array |
| Colors | `colors` | ColorPicker | jsonb column; stored as `[{hex:"#FF4500"}]` objects |
| Image | `image_primary` | file upload | Uploads to Supabase Storage, saves public URL string |
| Hover Image | `image_hover` | file upload | Uploads to Supabase Storage, saves public URL string |
| Stock | `stock` | number (integer, min 0) | Required |
| Description | `description` | textarea | Optional |

**Excluded from form:** `id` (UUID, auto-generated by Supabase), `created_at` (auto-set by Supabase default).

## Image Upload Behavior

- Supabase Storage bucket: `product-images` — **public** bucket (images are used on the public storefront)
- Bucket RLS: authenticated users can upload (`INSERT`) and update (`UPDATE`); public can read (`SELECT`)
- **On file select:** upload immediately → show an inline loading spinner on the thumbnail area → on success set URL in form state and show thumbnail preview → on error show a red error message ("Upload failed — try again") below the input; the form cannot be submitted if an image field is in error state
- **File path:** `products/${Date.now()}-${sanitizedFilename}`
- **On form submit:** the URL string already in state is saved; no re-upload on submit
- **Changing an image before saving:** the old upload is orphaned in storage (acceptable trade-off for simplicity; no cleanup on client side)
- **Edit mode:** image fields show the existing URL as a thumbnail + "Replace" button; clicking Replace shows the file input

## Slug Auto-generation

- Watch the `name` field with `useEffect`
- Generate: `.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')`
- Track whether the user has manually edited the slug with a `slugLocked` boolean ref (default `false`)
- `slugLocked = true` when user types in the slug field directly
- `slugLocked = false` (auto-generation resumes) when user **clears** the slug field entirely
- In edit mode, slug starts locked (preserves existing slug)
- **Uniqueness:** No unique constraint is assumed in the DB. On insert/update, if Supabase returns a unique-constraint error on `slug`, show an inline field error: "This slug is already taken — please choose another." The user must manually resolve it.

## Product List (AdminDashboard)

- Table columns: Image thumbnail (40×40px), Name, Category, Price (with sale price if set), Stock, Actions
- **Edit:** navigates to `/admin/products/:id`
- **Delete:** two-step inline confirmation — first click changes button text to "Confirm?" with a "Cancel" link next to it; second click triggers delete; Cancel resets back to "Delete". No modal, no `window.confirm()`.
  - While delete is in progress: show a small inline spinner, disable buttons
  - On error: show `"Delete failed"` in red next to the row; reset to normal state after 3 seconds
- Sorted by `id` descending (newest first)
- Shows loading skeleton (3 placeholder rows) while fetching
- No out-of-stock special styling in admin list

## ColorPicker Component

- Renders a row of color swatches for added colors
- "Add color" button opens a native `<input type="color">` + hex text field side by side
- On confirm: validate hex format, reject duplicates, append `{hex}` object to array
- Maximum 10 colors per product
- Each swatch has an ×  remove button
- Stored in form state as `[{hex:"#FF4500"}, ...]`

---

## TagInput Component

- Text input + Enter/comma to add a tag
- Renders tags as pills with × remove button
- Tags are freeform strings; no fixed options enforced by the component
- Stored in form state as plain string array e.g. `["Sale", "New Drop", "Nøiré Exclusive"]`

---

## Supabase Operations

- **List:** `supabase.from('products').select('*').order('id', { ascending: false })`
- **Insert:** `supabase.from('products').insert([formData])`
- **Update:** `supabase.from('products').update(formData).eq('id', id)`
- **Delete:** `supabase.from('products').delete().eq('id', id)`
- **Auth whitelist:** `supabase.from('admin_users').select('email').eq('email', userEmail).single()`

## Styling

- Background: `#0D0D0D` (brand-black)
- Accent: `#FF4500` (brand-orange)
- Text: white / `#E5E5E5`
- Subtle borders: `#2A2A2A`
- Row hover: `#1A1A1A`
- Headings: `Big Shoulders Display` + `Bebas Neue` fallback (matches site logo font)
- Body/labels: `DM Sans`
- Primary action (Save, Add): orange filled button with hover darken
- Secondary action (Cancel, Edit): zinc ghost button (`border border-[#3A3A3A]`)
- Destructive (Delete / Confirm?): `text-red-400` with `hover:text-red-300`
- No third-party admin component library

---

## Edit Mode — Data Fetch

- `ProductForm` reads `:id` from route params via `useParams()`
- On mount: `supabase.from('products').select('*').eq('id', id).single()`
- While fetching: show full-form loading skeleton
- If product not found (null or error): redirect to `/admin` immediately
- Image fields in edit mode: show existing URL as a thumbnail preview + "Replace" label above the file input. The existing URL is pre-populated in form state. The file input is empty (user must select a new file to replace).

---

## Decisions & Constraints

- Admin uses **Supabase Auth** (email + password), independent of Clerk (which handles shopper auth)
- `ProductsContext.jsx` is **unchanged** — it already reads the correct column names
- The `colors` column stores `[{hex: "#FF4500"}]` objects to match what `ProductsContext` already reads
- Categories: **Men, Women, Unisex** only
- `sale_price` is nullable; a value higher than `price` is permitted without warning (admin's responsibility)
- `stock` is an integer ≥ 0
- `image_primary` upload failure blocks form submission; `image_hover` is optional — its upload failure shows an error message but does not block submission
- Orphaned storage uploads from image replacement are not cleaned up (acceptable for an admin tool)
